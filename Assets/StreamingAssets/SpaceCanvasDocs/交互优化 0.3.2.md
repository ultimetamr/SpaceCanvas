# SpaceCanvas 0.3.2 交互优化

> 菜单已精简：默认仅显示“导入PICO工程 > 导入工程文件”。本文提及的 Tools > SpaceCanvas 开发菜单仅在启用 SPACECANVAS_DEVELOPER_MENUS 编译符号后显示；底层构建、验收和修复方法仍保留。

本版基于现有 Full Space MR 工作台。主场景为 `Assets/Scenes/SpaceCanvas_FullSpaceMR.unity`。

## 操作方式

- 射线点选物体后，使用底部的移动、旋转、缩放工具。
- 移动：拖动红 / 绿 / 蓝箭头，分别沿父节点 X / Y / Z 方向移动。
- 旋转：拖动彩色圆环。启用吸附时按 15° 步进。
- 缩放：拖动方形手柄，保持模型各方向比例。不同颜色手柄提供不同拖动方向，均为等比缩放。
- 按住扳机或捏合拖动，松开提交。一次拖动只生成一个撤销记录。
- 拖动回到原位不消耗撤销记录。跟踪丢失、失焦或打开模态窗口时，手柄拖动取消并恢复起始变换。
- 视线几乎正对轴线、或沿旋转平面边缘时，该方向无法稳定求交，保持原姿态；稍微换一个观察角度继续操作。
- 点空白处取消选择。没有选中物体时，属性区只显示引导。

## 属性面板

“位置与尺寸”页显示位置 / 旋转 / 尺寸、精确数值、轴约束与吸附。
“外观与配色”页显示颜色、四组预设、透明度、金属度与物理碰撞开关。
两页都可复制、删除当前物体。

配色预设通过原有 `colorHex` 字段实现，不替换贴图或共享材质；精细模型保留分部位颜色，以既有 tintStrength 混色。
“原始配色”恢复白色调色因子；透明度和金属度保持当前数值。

复制包含当前物体及其可编辑子物体，重新分配所有 ID 并保留内部父子关系；在父坐标 X 方向偏移 0.25 米。
副本不自动加入原有分组。一次复制可一键撤销，原物体保持原样。

## 开发接入

运行时核心仍不依赖 PICO SDK。`SpaceCanvasEditSession.Awake` 获取或创建 `SpaceCanvasTransformHandles`，
OpenXR 射线桥接 `Raycast / Hover / BeginDrag / Drag / EndDrag`。
手柄采用几何求交，不创建碰撞体，位于 ContentRoot 外，不会进入 JSON、撤销快照或物理模拟。
多指针以来源 ID 独占一段拖动，其他指针不能抢占。

新增文件：

- `SpaceCanvasHandleMath.cs`：轴线、平面、射线与线段求交。
- `SpaceCanvasTransformHandles.cs`：手柄绘制、命中与手势生命周期。
- `SpaceCanvasWorkspaceUI.Inspector.cs`：按需属性页、配色预设、事务式复制。
- `Tests/InteractionPolishTests.cs`：手柄、复制、配色与界面回归测试。

修改界面后运行 Unity 菜单 `Tools > SpaceCanvas > 重建 MR 界面与射线`，再构建 APK。
命令行可运行 `SpaceCanvas.ProjectIO.Editor.XR.SpaceCanvasFullSpaceBuilder.RebuildMRPresentationBatch`。
不要只修改脚本便使用旧场景打包；本版交付包含已重建的场景。

## 验证边界

EditMode 和 Editor 相机预览不等于头显验收。真机仍需检查手柄悬停 / 拖动手感、模态窗口开关与跟踪中断恢复。
本版没有增加真实房间平面识别或跨启动空间锚点，不宣称 Shared Space 原生多窗口。
既有恢复副本仍按 30 秒周期写入；突然强杀可能丢失尚未写入的编辑。
性能数据需从本次设备 Diagnostics 读取，不能用旧版本结果代替。
