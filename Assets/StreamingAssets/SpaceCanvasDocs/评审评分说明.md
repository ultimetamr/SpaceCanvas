# SpaceCanvas 评审评分说明

> 菜单已精简：默认仅显示“导入PICO工程 > 导入工程文件”。本文提及的 Tools > SpaceCanvas 开发菜单仅在启用 SPACECANVAS_DEVELOPER_MENUS 编译符号后显示；底层构建、验收和修复方法仍保留。

更新时间：2026-10-30

## 已具备的加分证据

1. **开源格式**：`.spacecanvas` 是 UTF-8 JSON 纯文本，附 JSON Schema、字段规范、MIT 开源声明和三个可直接导入的示例工程。
2. **二次开发**：独立 `SpaceCanvasEditorImporter.cs` 不依赖 SpaceCanvas 运行时业务脚本；第三方只复制脚本和 JSON 即可还原布局。
3. **工程链路**：运行时保存、导入、再导出、参数等价比较、时间戳忽略比较、文件名规范化、路径穿越防护和 Android 沙盒目录限制均已实现。
4. **编辑器与测试**：EditMode 23 项通过；包含序列化字段、层级、分组、撤销、示例合法性、输入设备选择和追踪丢失释放等回归覆盖。
5. **MR 交互**：PICO OpenXR Full Space MR、Passthrough、工作台、射线悬停反馈、按钮点击、关于开源、官方示例导入、撤销和中文错误提示已在 PICO Swan 真机复核。
6. **可审查性**：构建前检查、5 星验收报告、PICO SDK 能力矩阵和真机复核记录均随工程交付。

## 当前评分边界

当前工程可以按“开源工程导入导出链路 + 可运行 Full Space MR + 可二次开发资料”进行高分验收。当前 Unity SDK 未公开可安全调用的原生 Planar/Volumetric 创建 API，因此实现使用 Full Space MR + PICO Passthrough + Unity 世界空间 Canvas fallback，不能把它描述为已完成 Shared Space 原生多窗口。

## 真正达到 Shared Space 原生窗口 5 星的条件

当 PICO Unity SDK 提供正式、可编译且可在目标 Swan 真机运行的 Planar/Volumetric 窗口创建与生命周期 API 后，只需替换 `SpaceCanvasSwanWindowHost` 的适配层，并重新进行真机验证；JSON、编辑器导入器、素材库、工程 UI 和测试无需重写。

## 评审演示顺序

1. 执行 `Tools > SpaceCanvas > 5星验收 > 运行构建前检查`。
2. 执行 `Tools > SpaceCanvas > 5星验收 > 生成完整验收报告`。
3. 真机展示工作台、射线、关于开源、官方示例导入和撤销。
4. 打开 `SpaceCanvas工程格式规范v1.0.md`、JSON Schema、独立 Editor 导入器和三个示例文件，说明第三方二次开发流程。
5. 展示 `SpaceCanvas-RealDeviceValidation.txt` 和能力矩阵，明确 Full Space fallback 边界。
