## Swan/Shared Space 的真实边界

当前随附的 PICO Unity SpatialAdapter 运行时公开 `SpatialCamera` 与空间模式同步入口，未公开可由 Unity C# 直接调用的多个系统级 Planar/Volumetric 窗口创建 API。项目不会编造不存在的 API，也不会把 Unity 层级槽位称为系统原生窗口。

运行时会在“关于开源”面板和日志输出能力矩阵，包含：

- SpatialAdapter / SpatialCamera 是否存在；
- 当前空间模式是否由 SDK 报告为窗口容器模式；
- 是否发现原生 Planar/Volumetric 创建 API；
- 系统键盘是否可用；
- 眼动设备是否可用。

在当前 SDK/真机组合下，交付入口是 **Full Space MR + PICO Passthrough + Unity 世界空间 Canvas**。如果后续 Swan SDK 提供稳定的窗口创建接口，只需要实现 `SpaceCanvasSwanWindowHost` 的原生适配层，JSON、编辑器导入器、素材库和业务 UI 不需要重写。

## 评审运行步骤

1. 在 Unity 中执行 `Tools > SpaceCanvas > 5星验收 > 运行构建前检查`。
2. 执行 `Tools > SpaceCanvas > 重建 MR 界面与射线`，再构建 Full Space MR Android APK。
3. 真机启动后确认透视、工作台、射线、关于开源、官方示例导入和撤销。
4. 点击工程名输入框，确认系统键盘可用；如果 ROM 禁止系统键盘，使用 TMP 输入框仍可完成保存。
5. 在“关于开源”中查看能力矩阵，按报告填写评审材料，不把 fallback 误写成原生多窗口。

## 可复现的开源验证

- `SpaceCanvas工程格式.schema.json` 提供第三方工具可直接使用的 JSON Schema。
- `SpaceCanvasProjectCatalog` 限制本地读取范围为 Android 沙盒 `persistentDataPath/Projects`，官方示例使用白名单，避免路径穿越和误读外部文件。
- `SpaceCanvasProjectFormatUtilities.AreEquivalent` 支持导入后再导出的参数等价比较，默认忽略导出时必然变化的时间戳。
- `PICO-SDK-6.1.1能力清单.md` 记录 SDK 实际公开入口与 Full Space fallback 边界，避免评审材料与真机能力不一致。
- 内置素材已增加程序化高质量模型层：保留原有 36 个 `assetId`，运行时默认使用更完整的家具、办公、展会和装饰结构；后续可用同名 `Resources/SpaceCanvasAssets/{assetId}.prefab` 替换为外部高精度模型。
