# PICO 导入 Unity 后再次打包

## 原因与修复

旧版编辑器导入只在 Scene 根节点创建独立模型，并移除可编辑组件。这适合第三方静态布局还原，但在 SpaceCanvas MR 场景中，这组模型没有进入工作台 ContentRoot。应用仍注册原先的工作台内容，导入模型则使用世界根节点的缩放和坐标，出现两套布局。

现在“导入PICO工程 → 导入工程文件”按当前场景处理：

- 当前 Scene 有唯一 SpaceCanvasWorkspace：替换该工作台的可编辑工程内容，保留相机、UI、工作台布局，保留对象 ID、可编辑组件和分组；一次 Unity Undo 可撤销整次导入。
- 当前 Scene 无工作台：继续创建独立的布局根节点。第三方仍只需独立导入脚本，不依赖 SpaceCanvas/PICO 程序集。
- 多个工作台：报出明确错误，避免写入错误目标。

## 正确操作

1. 在 PICO 调整物体后点“保存工程”。未保存的编辑不会自动进入电脑。
2. Unity 打开 `Assets/Scenes/SpaceCanvas_FullSpaceMR.unity`。
3. 选择“导入PICO工程 → 导入工程文件”，核对保存版本与预览后确认。
4. 导入报告应显示“已导入 MR 工作台”，Hierarchy 的工程根在 `Editable Content` 内。旧独立导入的模型请在确认备份后用 Unity 撤销处理，或仅导入到干净的原工作台场景。
5. 保存 Scene 再 Build。项目的 Full Space 构建入口也会先保存已加载的目标 Scene；若编辑的工作台 Scene 与固定构建目标不同，会停止并提示，不会悄悄打包另一份布局。

## 坐标约定

JSON 的根对象位置、旋转与缩放相对于工程根；有 parentId 的对象相对于对应父物体。导入生成的工程根为单位变换，不额外中心化、自动适配尺寸或乘除工作台缩放。单位设置是显示制式，内部坐标始终按米保存。

工作台的舒适布局（距离、高度、整体展示大小）和头显启动回正属于展示设置，不等同于作品内物体位置。此格式没有真实房间空间锚点：重新启动后相对于现实房间的绝对位置不作跨会话保证。

## 验证

EditMode 回归覆盖非默认工作台位姿与缩放、父子对象不同缩放、JSON 导入再导出、磁盘 Scene 重载、启动注册、材质不重复染色、分组/单位保存及整体撤销。
